Docker

The official image runs the same server, with the world kept in a volume.

The image will be published with the server's first release as ghcr.io/karagra/voxelmon-server.

Run it

docker run -d -it --name voxelmon \
  --network host \
  --stop-timeout 20 \
  -v voxelmon:/data \
  ghcr.io/karagra/voxelmon-server:latest

docker logs voxelmon        # the join code is near the top
  • --network host: the server makes its join code from its own network address and answers codes on your network. Inside Docker's own private network it would see the wrong address, and players on your network could not find it.
  • -v voxelmon:/data: the world, server.toml and the blocked list live in the voxelmon volume, so they survive updates. Use a folder instead (-v /srv/voxelmon:/data) to edit server.toml directly.
  • --stop-timeout 20: docker stop asks the server to stop as the stop command does: players are told and the world is saved. This gives it time.
  • -it: keeps a console you can reach with docker attach voxelmon. Leave it with Ctrl-P then Ctrl-Q; Ctrl-C there stops the server.

Docker Compose

services:
  voxelmon:
    container_name: voxelmon
    image: ghcr.io/karagra/voxelmon-server:latest
    network_mode: host
    stdin_open: true
    tty: true
    restart: unless-stopped
    stop_grace_period: 20s
    volumes:
      - voxelmon:/data
volumes:
  voxelmon:
docker compose up -d
docker attach voxelmon

Settings

On its first run the server writes server.toml into /data. Edit it there (in the volume or your folder) and restart the container: docker restart voxelmon.

Updating

docker pull ghcr.io/karagra/voxelmon-server:latest
docker rm -f voxelmon
docker run ...              # as above; the volume keeps the world

To stay on one version, use its tag (for example :0.1.0) instead of :latest, and change it when your players update their game.

What is in the image

A small Debian base, the Linux server and Epic's library. The server runs as its own limited user, voxelmon, which can write only to /data.
