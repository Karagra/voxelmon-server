Events

Being built. 15 of 55 events are sent by servers today; the rest are marked not yet.

Everything a plugin can react to. Some events come before something happens and can stop it; the rest say it has happened.

A plugin listens by giving a handler for the event, usually in enable: in Rust server.events().on_player_joined(|event| ...), in Java server.events().onPlayerJoined(event -> ...). Events come on the server's tick, in the order the plugins loaded.

An event that can be stopped is sent before the thing happens, and its name says so (for example BlockBreaking); calling stop() on it means it does not happen, and the player's game puts back what it showed. Fields marked changeable can be changed by a listener before it happens (the damage taken, the loot dropped). The event after it (BlockBroken) says it did happen, and cannot be stopped.

Listening

A plugin listens in enable; a handler gets the event, can read every field and, where the event allows, stop it or change the fields marked changeable. Handlers run in the order plugins loaded, each seeing the last one's changes.

server.events().on_block_breaking(|event| {
    if event.block.at.y < 0 {
        event.stop();
    }
})?;
server.events().onBlockBreaking(event -> {
    if (event.block().at().y() < 0) {
        event.stop();
    }
});
