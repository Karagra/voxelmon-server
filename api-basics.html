Writing a plugin

What a plugin is made of, and how the server starts and stops it.

Being built. Plugins run on the server today; part of the API works so far (the reference marks the rest not yet). Names may change until the first plugin release.

Your first Rust plugin

You need Rust (rustup) with the WebAssembly target, and the server's download, whose sdk/rust/ holds the plugin kit:

rustup target add wasm32-unknown-unknown

A plugin is a library crate built as a cdylib:

hello/
  Cargo.toml
  plugin.toml
  src/lib.rs

Cargo.toml:

[package]
name = "hello"
version = "1.0.0"
edition = "2024"

[lib]
crate-type = ["cdylib"]

[dependencies]
voxelmon-plugin-sdk = { path = "path/to/server/sdk/rust/voxelmon-plugin-sdk" }

[profile.release]
opt-level = "s"
lto = true
panic = "abort"
strip = true

plugin.toml (below, the manifest):

id = "hello"
name = "Hello"
version = "1.0.0"
api = "1"
needs = []

src/lib.rs:

use voxelmon_plugin_sdk::*;

struct Hello;

impl Plugin for Hello {
    fn enable(server: &Server) -> Self {
        let _ = server.events().on_player_joined(|event| {
            if let Ok(name) = event.player.called() {
                let _ = Server.log_info(&format!("Hello, {name}!"));
            }
        });
        Hello
    }
}

voxelmon_plugin!(Hello, "../plugin.toml");

Build it, and copy the .wasm into the server's plugins/ folder:

cargo build --release --target wasm32-unknown-unknown
cp target/wasm32-unknown-unknown/release/hello.wasm path/to/server/plugins/

Start the server (or type plugin reload hello in a running one); it lists the new plugin and what it needs. Type plugin approve hello and it loads. The manifest goes inside the .wasm file, so the one file is the whole plugin. Every call returns voxelmon_plugin_sdk::Result; a call a server does not carry out yet fails with Error::Failed saying so.

A fuller example is in the download: sdk/examples/rust/spawn-guard (joins counted in storage, blocks round spawn kept unbroken, a console command).

Your first Java plugin

You need a JDK, version 25 or newer, and the server's download, whose sdk/java/ holds voxelmon-api.jar (and its sources, for your editor). The server needs Java 25 too, to run Java plugins.

hello/
  plugin.toml
  src/com/example/hello/Hello.java

plugin.toml names the main class:

id = "hello"
name = "Hello"
version = "1.0.0"
api = "1"
main = "com.example.hello.Hello"
needs = []

Hello.java:

package com.example.hello;

import net.voxelmon.api.Server;
import net.voxelmon.api.VoxelmonPlugin;

public final class Hello extends VoxelmonPlugin {
    @Override
    public void enable(Server server) {
        server.events().onPlayerJoined(event ->
                server.logInfo("Hello, " + event.player().called() + "!"));
    }
}

Build the jar with plugin.toml at its root, and copy it into plugins/:

javac --release 25 -cp path/to/server/sdk/java/voxelmon-api.jar -d classes $(find src -name '*.java')
cp plugin.toml classes/
jar --create --file hello.jar -C classes .
cp hello.jar path/to/server/plugins/

Then plugin approve hello, as for Rust. A call a server cannot carry out throws ApiException; a value that may be missing is an Optional. Java plugins are started when the server starts: a jar added to a running server waits for a restart. The download's sdk/examples/java/welcome is a fuller example with a build script.

Values

Storage, settings and services between plugins hold a Value: text, a whole number, a number with a fraction, true or false, a list of values, or a table of named values. Tables and lists may hold values in turn, nested up to 32 deep.

KindRustJava
TextValue::Text(String)Value.of("text") / Value.Text
Whole numberValue::Int(i64)Value.of(5L) / Value.Int
NumberValue::Float(f64)Value.of(0.5) / Value.Float
True or falseValue::Bool(bool)Value.of(true) / Value.Bool
ListValue::List(Vec<Value>)new Value.ListValue(List.of(...))
TableValue::Table(Vec<(String, Value)>)new Value.Table(Map.of(...))

Reading one back, Rust has as_str(), as_int(), as_float(), as_bool() and get_key("name") for a table's entry, each an Option; in Java, Value is a sealed interface, read with a switch or instanceof on its records:

let joins = server.storage().get("joins")?.and_then(|v| v.as_int()).unwrap_or(0);
server.storage().set("joins", Value::Int(joins + 1))?;
long joins = server.storage().get("joins")
        .map(v -> v instanceof Value.Int n ? n.value() : 0L).orElse(0L);
server.storage().set("joins", Value.of(joins + 1));

When a call fails

In Rust every call returns voxelmon_plugin_sdk::Result<T>, whose error is an Error; in Java a call that fails throws ApiException, whose kind() says which:

Rust ErrorJava ApiException.KindMeaning
GoneGONEWhat it was about is gone: a player who left, a creature beaten, a menu removed.
Denied(need)DENIEDThe plugin's manifest does not ask for the need this call has (needs); the text names it.
InvalidINVALIDAn argument was out of range or malformed: text too long, a stack over its limit, an unknown item.
LimitLIMITA limit was reached: too many tasks, commands or stored keys, a fill too large.
Failed(why)FAILEDIt could not be done; the text says why. A call the server does not carry out yet fails this way, saying it is not available yet, and does nothing else.

A call that changes the world, made while a stoppable event is being decided (inside a handler that may stop() it), is carried out as soon as that event is over if it returns nothing; one that returns something fails then.

Limits

Rust pluginsJava plugins
TimeA call into the plugin taking over 250 ms is stopped, and the plugin disabled.Over 20 ms is reported in the console; nothing can stop a Java call.
Memory64 MB at most.Java's own heap, shared by every Java plugin.
What it can reachOnly the server's calls, and only those its manifest's needs allow.The server's calls, and anything Java itself can do as the server's user.
Its datastorage() values are kept in plugins/<id>/data.bin; files (the files need) in plugins/<id>/files/.

A call that takes over 20 ms is reported either way, and plugins shows how much time each plugin has taken.

Where plugins go

Each plugin is one file in the server's plugins/ folder: a .wasm file (Rust) or a .jar file (Java). The first time the server sees a new or changed file it lists it and what it needs, and waits for the owner to approve it with the plugin approve command; approvals are kept in plugins/approved.toml, each for that file's SHA-256. Approved plugins load in the order their dependencies need.

The manifest

Every plugin carries a plugin.toml:

id = "warps"                # unique, lowercase letters, digits and dashes
name = "Warps"
version = "1.2.0"
api = "1"                   # the API version it was built for
authors = ["Karagra"]
description = "Named places players can travel to."
depends = []                # plugins that must load first
soft_depends = ["economy"]  # used if present
needs = ["files"]           # what it asks the server for (below)
main = "com.example.warps.Warps"  # Java plugins only: the main class

Needs

NeedAllows
filesReading and writing in its own folder, plugins/<id>/
internetHTTP requests to the internet (the hosts listed in internet_hosts)
world_editChanging blocks and placed objects
player_dataChanging players' bags, gear, coins, progress and teams
creaturesSpawning, changing and removing Voxelmon

Reading the world and players needs nothing. A Rust plugin asking for something its manifest does not list is refused; the owner sees what each plugin needs before approving it.

Lifecycle

CallWhen
enable(server)The plugin is loaded: register events, commands and tasks here.
disable()The server is stopping or the plugin is being reloaded: save what it keeps.
world_ready()The world has loaded and players may join.

The server ticks 60 times a second. Plugin code runs on the server's tick between steps of the world; a call that takes too long is reported in the console and in status.

Settings

CallWhat it does
config()The plugin's plugins/<id>/config.toml, written from its defaults the first time
config.get(key) / get_or(key, default)A setting: text, number, true/false, list or table
config.reload()Read the file again (also by the plugin reload command)

Logging

CallWhat it does
log.info(text), log.warn(text), log.error(text)A line in the server's console, marked with the plugin's name

Console commands for plugins

CommandWhat it does
