Plugins and content packs

Planned: ways for server owners and creators to add to VoxelMon worlds. Nothing here is available yet; this page grows as each part is built.

Three kinds

KindWhat it addsWritten in
Content packsNew items, blocks, recipes, loot and where creatures appear. Data only, no code. Players' headsets download a server's packs when they join, after asking them.Data files
Rust pluginsServer behaviour: commands, events, rules, minigames, permissions. Run sandboxed: a plugin can touch only what the server hands it.Rust, compiled to WebAssembly
Java pluginsThe same, for authors who know Java. Run with the server's full trust, like plugins on other block-game servers. Java is started only on a server that has a Java plugin.Java (.jar)

Plugins run on the server only. Headsets never run plugin code; they receive only what the plugins change in the world, and the data of content packs.

One API for both languages

Rust and Java plugins see the same API: the same events, commands, permissions and scheduler, generated from one definition, so a feature reaches both at once and their documentation never disagrees. Its reference will be published here.

Safety

  • A server owner approves each plugin by its exact file; a changed file needs approving again. Nothing updates itself.
  • Each plugin says what it needs (for example, saving files or reaching the internet), and Rust plugins get nothing else.
  • Content packs have hard size limits, and the headset checks every file before using it.
  • Run the server under its own user or in Docker, so a plugin with full trust can reach only the server's own folder.
