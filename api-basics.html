Writing a plugin

What a plugin is made of, and how the server starts and stops it.

Planned. Names may change until the first plugin release.

Where plugins go

Each plugin is one file in the server's plugins/ folder: a .wasm file (Rust) or a .jar file (Java). The first time the server sees a new or changed file it lists it and waits for the owner to approve it with the plugin approve command. Approved plugins load in the order their dependencies need.

The manifest

Every plugin carries a plugin.toml:

id = "warps"                # unique, lowercase letters, digits and dashes
name = "Warps"
version = "1.2.0"
api = "1"                   # the API version it was built for
authors = ["Karagra"]
description = "Named places players can travel to."
depends = []                # plugins that must load first
soft_depends = ["economy"]  # used if present
needs = ["files"]           # what it asks the server for (below)

Needs

NeedAllows
filesReading and writing in its own folder, plugins/<id>/
internetHTTP requests to the internet (the hosts listed in internet_hosts)
world_editChanging blocks and placed objects
player_dataChanging players' bags, gear, coins, progress and teams
creaturesSpawning, changing and removing Voxelmon

Reading the world and players needs nothing. A Rust plugin asking for something its manifest does not list is refused; the owner sees what each plugin needs before approving it.

Lifecycle

CallWhen
enable(server)The plugin is loaded: register events, commands and tasks here.
disable()The server is stopping or the plugin is being reloaded: save what it keeps.
world_ready()The world has loaded and players may join.

The server ticks 60 times a second. Plugin code runs on the server's tick between steps of the world; a call that takes too long is reported in the console and in status.

Settings

CallWhat it does
config()The plugin's plugins/<id>/config.toml, written from its defaults the first time
config.get(key) / get_or(key, default)A setting: text, number, true/false, list or table
config.reload()Read the file again (also by the plugin reload command)

Logging

CallWhat it does
log.info(text), log.warn(text), log.error(text)A line in the server's console, marked with the plugin's name

Console commands for plugins

CommandWhat it does
pluginsPlugins found, approved and loaded, with their needs
plugin approve IDApproves a new or changed plugin file and loads it
plugin reload IDDisables and enables a plugin again
plugin disable IDStops a plugin until it is enabled again
