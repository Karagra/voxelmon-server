Events

Planned. The plugin API is being built: nothing here can be used yet, and names may change until the first plugin release.

Everything a plugin can react to. Some events come before something happens and can stop it; the rest say it has happened.

A plugin listens by naming the event: in Rust a method on its plugin, in Java a method marked @Listen. Events come on the server's tick, in the order the plugins loaded; a plugin can ask to hear an event first or last (order = early or late).

An event that can be stopped is sent before the thing happens, and its name says so (for example BlockBreaking); calling stop() on it means it does not happen, and the player's game puts back what it showed. Fields marked changeable can be changed by a listener before it happens (the damage taken, the loot dropped). The event after it (BlockBroken) says it did happen, and cannot be stopped.

PlayerJoining

A player has proved who they are and is about to enter the world.

Can be stopped: the player is turned away with `reason`.

TypeFieldDescription
PlayerProfileprofileTheir store account's name and lasting ID, and whether they have played here before.
Stringreason changeableWhat they are told if stopped.

TypeFieldDescription

A player has left: by choice, put out, or their connection ended.

TypeFieldDescription
