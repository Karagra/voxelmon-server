Plugins and content packs

Ways for server owners and creators to add to VoxelMon worlds.

Built. Rust and Java plugins run on the server and every call and event of the API is carried out. Notices, banners, menus and floating labels reach players' headsets. Content packs add loot, wild spawns, models, objects, species, moves, items, recipes and shop goods; packs that add sounds, new blocks or world generation are still to come. Names may change until the first plugin release.

Three kinds

KindWhat it addsWritten in
Content packsMore loot and where creatures appear; models, objects, species, moves, items, recipes and shop goods of their own. Data only, no code.Data files
Rust pluginsServer behaviour: events, rules, menus, minigames, permissions. Run sandboxed: a plugin can touch only what the server hands it.Rust, compiled to WebAssembly
Java pluginsThe same, for authors who know Java. Run with the server's full trust, as plugins do on other block-game servers. Java (25 or newer) is started only on a server that has a Java plugin.Java 25+ (.jar)

Plugins run on the server only. Headsets never run plugin code; they receive what plugins change in the world, the menus and messages plugins show, and the data of content packs.

One API for both languages

No text chat

VoxelMon is played in VR with no keyboard and no text chat. Plugins reach players through notices, banners and menus, and players act through menus and what they do in the world. Console commands are for the server's owner.

Safety

  • A server owner approves each plugin by its exact file; a changed file needs approving again. Nothing updates itself.
  • Each plugin's manifest says what it needs (saving files, reaching the internet); Rust plugins get nothing else.
  • Content packs have hard size limits, and the headset checks every file before using it.
  • Run the server under its own user or in Docker, so a plugin with full trust can reach only the server's own folder.
